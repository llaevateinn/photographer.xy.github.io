# 爱云动 · 赛事摄影调度 Demo

一个面向赛事运营的离线单页工作台。应用使用内置样例数据或用户导入的 CSV，测算摄影师需求、生成排班建议、筛选激活人选并提示风险。无需账号、后端或网络服务；数据保存在当前浏览器的 `localStorage` 中。

## 环境要求

- Windows、macOS 或 Linux 桌面环境
- Node.js 18 或更高版本（建议使用 Node.js 20 LTS）
- pnpm 9 或更高版本

本项目为 JavaScript/TypeScript 项目，依赖由 `package.json` 声明、`pnpm-lock.yaml` 锁定。`requirements.txt` 是便于评审查看的工具与依赖清单，不是 Python/pip 清单。

## 安装与运行

在项目根目录执行以下命令：

```bash
pnpm install --frozen-lockfile
pnpm dev -- --host 127.0.0.1 --port 5173
```

然后在浏览器打开 <http://localhost:5173/>。Vite 默认使用 5173 端口；端口被占用时，可在启动命令中更换端口，例如 `--port 5174`。

没有安装 pnpm 时，可通过 Corepack 启用后再执行安装：

```bash
corepack enable
corepack prepare pnpm@9 --activate
pnpm install --frozen-lockfile
```

## 验证与生产构建

## 输入说明

### 赛事需求表

上传、粘贴或直接粘贴 CSV 均可。CSV 必须有完整表头，字段为：

| 字段 | 含义 / 格式 |
| --- | --- |
| `event_id` | 唯一赛事 ID |
| `city` | 赛事城市 |
| `event_date` | 日期，建议使用 `YYYY-MM-DD` |
| `participants` | 参赛人数，正数 |
| `course_km` | 赛道长度（公里），正数 |
| `time_window_hours` | 拍摄时长（小时），正数 |
| `night_race` | 是否夜跑：`yes` 或 `no` |
| `difficulty` | 难度 1–5 |

### 摄影师供给表

字段为：

| 字段 | 含义 / 格式 |
| --- | --- |
| `photographer_id` | 唯一摄影师 ID |
| `home_city` | 常驻城市 |
| `price_per_event` | 单场报价，非负数 |
| `rating` | 评分，0–5 |
| `last_active_days` | 距最近活跃天数，非负整数 |
| `skill_tags` | 技能标签，使用 `|`、`/` 或 `;` 分隔 |
| `available` | 当前是否可接单：`yes` 或 `no` |

导入时可选择替换当前表或在原数据基础上添加。追加数据不允许与现有 ID 重复。系统按 CSV 表头识别表类型；导入失败会展示行号、字段和原因，并保留原数据。两张表都支持排序、手动新增、逐行删除和一键清空；删除及清空可撤回。当前数据可下载为 `events.csv` 或 `photographers.csv`。

可用项目内的 `赛事需求表示例.csv` 与 `摄影师供给表示例.csv` 试导入；每份文件包含完整表头和两条示例记录。

## 输出说明

| 文件 | 内容 |
| --- | --- |
| `staffing_plan.csv` | 每场赛事的推荐人数、基准人数、预计成本、预算上限和超预算状态 |
| `assignments.csv` | 赛事与摄影师分配、摄影师报价、跨城状态及分配理由 |
| `activation_list.csv` | 激活排名、摄影师信息、预估报酬区间及可编辑召回话术 |
| `events.csv` / `photographers.csv` | 当前赛事需求表或摄影师供给表 |
| JSON 存档文件 | 当前输入数据、测算参数、话术编辑和快照数据，可从手动存档菜单导入/导出 |

CSV 文件通过浏览器下载。召回话术在本地按模板生成，不会调用生成式 AI 或外部接口。

## 功能概览

- **数据**：赛事和摄影师 CSV 上传/拖放/粘贴、剪贴板识别、校验、追加/替换、手动编辑式管理、下载与恢复默认。
- **需求测算**：覆盖率、照片量、精品率、单人产能和赛事修正系数可用滑块或数值输入调整；单人每场预算可编辑。参数变化后结果自动重算。
- **排班建议**：按赛事展示候选摄影师、成本、供给缺口、跨城调度及选择理由。
- **激活召回**：提供最多 10 名可接单且评分达标的摄影师，话术可编辑、复制和导出。
- **风险提示**：显示供给不足、成本、评分及跨城等风险，并可跳转到相关页面。
- **本地存档**：浏览器自动保存；支持命名快照、快照恢复和 JSON 文件备份。

## 关键假设与取舍

- **完全本地运行**：不含服务端、数据库、登录和网络 API。浏览器 `localStorage` 仅对当前浏览器配置文件有效；清理站点数据或更换浏览器前，应导出 JSON 存档备份。
- **样例数据仅用于演示**：首次使用内置 6 场赛事和 16 名摄影师，不代表真实业务供给或报价。导入用户 CSV 后，测算与各模块会自动级联更新。
- **需求测算是可调的运营估算**：默认覆盖率 85%、每位覆盖参赛者需要 3 张有效照片、精品率 60%、单人每小时原片 500 张；夜跑、高难度和全马分别使用 0.85、0.90、0.95 修正系数。它们是规划假设，不是对实际交付结果的承诺。
- **预算口径与实际报价分开**：默认预算上限为推荐人数 × 每人每场 ¥700；排班成本按被选摄影师各自的单场报价合计。调整每人预算只改变预算上限，不重写摄影师报价。
- **排班是规则型建议**：可接单状态、复杂赛事的评分下限和同日不可重复排班是硬约束；同城优先、夜拍标签和激活沉睡人员等属于排序偏好。候选不足时展示缺口，不虚构人员。
- **离线能力范围**：页面和内置计算不依赖网络；依赖安装、首次加载远程字体/浏览器功能则不属于离线保证范围。数据仅在浏览器本地保存。
